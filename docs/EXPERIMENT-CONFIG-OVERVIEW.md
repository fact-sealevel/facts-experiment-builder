# Experiment Configuration File

`experiment-config.yaml` is the core artifact of a FACTS2 experiment. It is generated by `feb setup-experiment` and lives in your experiment's subdirectory (e.g., `experiments/my_experiment/experiment-config.yaml`). It fully specifies the experiment — which modules to run, with what parameters, on what data — but does not execute anything. Once complete, it drives `feb generate-compose`.

---

## What you need to fill in

After `feb setup-experiment` runs, most fields are pre-populated from module defaults and your CLI arguments. The fields that typically require manual attention are:

| Field | Section | What to do |
|---|---|---|
| `pipeline-id` | Top-level params | Set a unique identifier for this run (e.g. `my-experiment-ssp585`) |
| `module-specific-input-data` | Inputs | Absolute or relative path to your `module_specific_input_data/` directory |
| `shared-input-data` | Inputs | Absolute or relative path to your `shared_input_data/` directory |
| Any field with only a `# hint` and no value below it | Module sections | Required inputs the tool could not pre-fill — you must supply a value |

Fields marked `# filename from module defaults` or `# value from module defaults` already have a value — review them but you usually don't need to change them.

The `image:` field and everything under `outputs:` in each module section are set by the module and **should not be edited**.

## Example 2: Experiment with emulandice2 modules

Experiments using `emulandice2` modules differ from the standard pattern in a few ways. Below are the key sections that look different; sections not shown follow the same structure as Example 1.

**emulandice2 module section** — the `emu_file` input is a list of emulator build files (one per region), and `fingerprint_params` includes an extra `grdfingerprintfile` field:

```yaml
emulandice2-ais:
  inputs:
    climate_data_file:
      # Fair output or tlm data
      "fair-temperature/climate.nc"    # filename from module defaults
    r_script_path:
      # Path to the R script to launch emulandice2.
                                      
    emu_file:
      # Emulation file(s) — one per region
      - emu_file/AIS_PEN_2300_260601_EMULATOR.RData
      - emu_file/AIS_WAIS_2300_260601_EMULATOR.RData
      - emu_file/AIS_EAIS_2300_260601_EMULATOR.RData
  options:
    # Options inherited from top-level metadata: pipeline-id, location-file, scenario,
    # pyear-start, pyear-end, pyear-step, baseyear
    ice_source:
      # For Antarctic Ice Sheet, ice-source is always AIS
      AIS   # value from module defaults
    region:
      - PEN
      - WAIS
      - EAIS
    seed:
      # Random seed for reproducibility.
      2024  # value from module defaults
  image: "ghcr.io/fact-sealevel/emulandice2:edge"   # do not edit
  outputs:    # do not edit
    output-gslr-file:
      value: "emulandice2-ais/output-gslr-AIS.nc"
      output_type: global
    output-lslr-file:
      value: "emulandice2-ais/output-lslr-AIS.nc"
      output_type: local
  fingerprint_params:
    grdfingerprintfile:
      # File containing the grd fingerprint map
      grd_fingerprintmap.yml    # filename from module defaults — in shared-input-data/
    fingerprint_dir:
      # Directory containing the fingerprint files
      FPRINT                    # value from module defaults — subdirectory in shared-input-data/
```

## Key concepts

**Blank clue fields** — A field that has only a `# hint comment` with no value on the next line is one the tool could not pre-fill. You must supply a value before running `feb generate-compose`. Example:

```yaml
pipeline-id:
        # Pipeline ID
                    # <- no value; you must fill this in
```

**`# filename from module defaults`** — The value is the filename the module expects to find in its input directory. You usually don't need to change it, but verify your downloaded data matches.

**`# value from module defaults`** — A scalar parameter pre-filled from the module's defaults. Review it, but you usually don't need to change it.

**`inputs` vs `fingerprint_params`** — Both hold input file references but they route to different directories. Fields under `inputs` are looked up inside `module-specific-input-data/<module-name>/`. Fields under `fingerprint_params` are looked up inside `shared-input-data/`. This routing is handled automatically by `feb generate-compose`.

**`climate_data_file`** — Several sea-level modules list the temperature module's output (e.g. `"fair-temperature/climate.nc"`) as an input. This path is resolved automatically at compose-generation time; you do not need to change it.

**`outputs`** — Output filenames are determined by the module. Do not edit them; `feb generate-compose` reads these to wire up dependencies between services (e.g. so facts-total knows where each sea-level module wrote its output).

**Multiple workflows** — Each workflow in the `workflows:` section causes `facts-total` to run once, summing the listed modules. Use multiple workflows to compare different combinations of sea-level contributions in a single experiment run. See the [FACTS Glossary](FACTS_GLOSSARY.md) for more detail.
