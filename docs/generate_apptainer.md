# `generate-apptainer` user guide

`generate-apptainer` reads an existing `experiment-config.yaml` and produces a bash script (`experiment-apptainer.sh`) that runs the same FACTS sea-level experiment using Apptainer instead of Docker Compose. It is the Apptainer equivalent of `generate-compose`.

---

## Prerequisites

- **Apptainer** installed on the machine where you will run the experiment.
- **[uv](https://docs.astral.sh/uv/)**, to run FEB with `uvx`. `generate-apptainer` is currently only on the `add_apptainer_command` branch, so run it from that branch without installing anything:
  ```bash
  uvx --from git+https://github.com/fact-sealevel/facts-experiment-builder@add_apptainer_command feb generate-apptainer --help
  ```
  The branch changes as work continues. `uvx` caches the version it installs, so add `--refresh` to pick up the latest commits on the branch:
  ```bash
  uvx --refresh --from git+https://github.com/fact-sealevel/facts-experiment-builder@add_apptainer_command feb generate-apptainer --help
  ```
- An `experiment-config.yaml` that was generated by `setup-experiment` for the experiment you want to run.

---

## Workspace and data setup

### Setting up the workspace

`generate-apptainer` expects a FACTS workspace prepared the same way as for `generate-compose`. Run these steps from the directory you want to use as your workspace; it becomes the `--workspace-dir` for every later command. (The commands below use `uvx` from this branch, as described in [Prerequisites](#prerequisites).)

1. **`feb init`** creates the workspace: an `experiments/` directory, a clone of the module registry in `facts-module-registry/` (added to `.gitignore`), and a `.facts-workspace` marker file.
   ```bash
   uvx --from git+https://github.com/fact-sealevel/facts-experiment-builder@add_apptainer_command feb init
   ```
2. **Download the input data** by following the instructions in the FEB documentation ([`docs/module_input_data_downloads.md`](module_input_data_downloads.md)). These create `data/shared_input_data/` and `data/module_specific_input_data/` and download the files each module needs into them. `feb init` does not create `data/`.
3. **`feb check-data`** checks the downloaded data against the module registry: for every module that has a directory in `data/module_specific_input_data/`, it verifies the expected input files are present, and it checks `data/shared_input_data/`. Run it from the workspace root; its defaults (`--data-dir ./data`, `--module-registry ./facts-module-registry`) match the layout above.
   ```bash
   uvx --from git+https://github.com/fact-sealevel/facts-experiment-builder@add_apptainer_command feb check-data
   ```

After that, create the experiment with `feb setup-experiment` (passing `--module-specific-input-data data/module_specific_input_data` and `--shared-input-data data/shared_input_data`), then run `generate-apptainer`. The experiment's parent directory (e.g. `experiments/`, or `apptainer_experiments/` in the examples below) must already exist; `setup-experiment` does not create it.

### Resulting layout

All paths below are relative to your `--workspace-dir`.

```
workspace/
├── .facts-workspace                ← created by feb init
├── facts-module-registry/          ← created by feb init (module YAMLs)
├── experiments/                    ← created by feb init (default parent for experiments)
├── data/                           ← created by the input data download instructions
│   ├── shared_input_data/          ← shared across all modules
│   │   ├── location.lst
│   │   └── FPRINT/
│   └── module_specific_input_data/ ← one subdirectory per module
│       ├── fair-temperature/
│       ├── fittedismip-gris/
│       ├── ipccar5/                ← shared by ipccar5-glaciers AND ipccar5-icesheets
│       └── ...
└── apptainer_experiments/
    ├── sif/                        ← Apptainer image files (.sif), created by the script — see note below
    └── {experiment_name}/          ← any experiment directory works, e.g. experiments/{experiment_name}
        ├── experiment-config.yaml  ← required input (from setup-experiment)
        ├── experiment-apptainer.sh ← generated output (created by this command)
        └── output-apptainer/       ← Apptainer outputs (created by this command)
```

### Shared input data (`data/shared_input_data/`)

Contains files shared across modules for a given location set, primarily:

| File/directory | Purpose |
|---|---|
| `location.lst` | Target site location list |
| `FPRINT/` | Gravitational fingerprint files |

The path to this directory is set in `experiment-config.yaml` under `shared-input-data`.

### Module-specific input data (`data/module_specific_input_data/`)

Each module has its own subdirectory containing the input files that module needs (parameter files, scenario data, etc.). The directory name matches the module's `input_dir_name` from its module YAML — usually the module name, but multi-command modules that share an image share a directory (e.g. both `ipccar5-glaciers` and `ipccar5-icesheets` read from `ipccar5/`).

The path to the base directory is set in `experiment-config.yaml` under `module-specific-input-data`.

### SIF files (`apptainer_experiments/sif/`)

This directory stores Apptainer image files. **You do not need to populate it before running the script** — the generated script includes a `pull_image` helper that downloads each image automatically if the `.sif` file is not already present.

However, if you want to pre-populate SIF files to avoid downloading at run time, note that `generate-apptainer` uses **versioned filenames**: `{module-name}-{image-tag}.sif` (e.g. `fair-temperature-0.2.1.sif`). This differs from older hand-authored scripts that used unversioned names (`fair-temperature.sif`). Existing unversioned SIF files will not be reused by the generated script; the script will pull fresh versioned copies.

SIF files are shared across experiments in the workspace — once `fair-temperature-0.2.1.sif` is pulled for one experiment, any other experiment using the same image version will reuse it.

### Output data

Apptainer runs write to a separate output directory inside the experiment directory:

```
{experiment_dir}/output-apptainer/
```

This is **not** `output-data-location` from `experiment-config.yaml`, which is used by `generate-compose`. Keeping them separate lets you run the same experiment with both Docker Compose and Apptainer without the outputs overwriting each other.

`generate-apptainer` creates `output-apptainer/` and one subdirectory per service when it generates the script (the script also runs `mkdir -p` on them). You do not need to create them in advance.

## Running `generate-apptainer`

```bash
uvx --from git+https://github.com/fact-sealevel/facts-experiment-builder@add_apptainer_command feb generate-apptainer \
  --experiment-name apptainer_experiments/small_coupling \
  --workspace-dir /path/to/workspace
```

The `--experiment-name` is a path relative to `--workspace-dir` pointing to the directory that contains `experiment-config.yaml`. It can be a bare name (`small_coupling`) or include a parent directory (`apptainer_experiments/small_coupling`).

`--workspace-dir` defaults to the current working directory if omitted.

### All options

| Option | Required | Default | Description |
|---|---|---|---|
| `--experiment-name` | yes | — | Path to experiment directory, relative to workspace |
| `--workspace-dir` | no | `$PWD` | Root workspace directory |
| `--custom-script-path` | no | — | Override output path for the generated script |
| `--debug` | no | off | Enable verbose debug logging |

---

## Output

The command writes `experiment-apptainer.sh` into the experiment directory and makes it executable. The script:

1. Defines path and parameter variables (baked in from your config at generation time).
2. Creates output directories.
3. Pulls all required Apptainer images (skipping any already present in `sif/`). Each image is pulled by its full reference from its module YAML (e.g. `ghcr.io/fact-sealevel/fair-temperature:0.2.1`), so modules may come from different registries.
4. Runs modules in four stages:
   - **Stage 1** — Climate module + sealevel modules with no climate dependency (sequential).
   - **Stage 2** — Sealevel modules that consume climate output, gated by `wait_for_output` polls (sequential).
   - **Stage 3** — Totaling step, one job per workflow × output type, run in parallel (`&`) then waited on.
   - **Stage 4** — ESL modules: one per workflow, or one per ESL module if the experiment has no workflows (sequential).

Each module runs with the same command-line arguments as its `experiment-compose.yaml` service. In particular, totaling services receive the same inputs as in Compose: outputs whose module YAML sets `pass_to_total: false` are excluded, and all other outputs of the matching type are included. Inputs a module YAML declares with `envvar` are passed to the container as environment variables (`--env`), as Compose passes them under `environment:`.

## Running the generated script

```bash
bash /path/to/workspace/apptainer_experiments/small_coupling/experiment-apptainer.sh
```

Or, since the script is made executable on generation:

```bash
/path/to/workspace/apptainer_experiments/small_coupling/experiment-apptainer.sh
```

The script uses `set -euo pipefail`, so it will exit immediately on any error.

**Run it with `bash`, not `sh`.** The script is bash-only. On systems where `sh` is a different shell (e.g. `dash` on Ubuntu/Debian, the default in Lima VMs), `sh experiment-apptainer.sh` fails immediately with `set: Illegal option -o pipefail`.

### Generating on one machine, running in a VM (e.g. Lima)

Paths in the script are host paths fixed at generation time, and `generate-apptainer` creates the output directories when it runs. A typical flow when Apptainer only runs inside a VM:

1. Run `generate-apptainer` on the host. The workspace must be at a path the VM mounts at the same location, with write access, so the baked-in paths are valid inside the VM.
2. Start a **new** VM session, so the newly created output directories are visible through the mount.
3. Inside the VM, run the script with `bash` (see above).

## Notes

- **Paths are baked in at generation time.** If you move the workspace after running `generate-apptainer`, regenerate the script from the new location.
- **SIF files are version-pinned.** If an image tag changes in `experiment-config.yaml`, re-run `generate-apptainer` and the script will reference the new versioned SIF name. The old SIF file remains in `sif/` and can be deleted manually.
- **The script does not modify `experiment-config.yaml`.** It is safe to regenerate the Apptainer script at any time without affecting your experiment configuration.
- **Containers start in `/`.** Services run with `--containall --no-home`, so your home directory is not available inside the container; `--pwd /` avoids a harmless "Error changing the container working directory" warning. All module paths are absolute container paths, so the working directory does not affect results.
